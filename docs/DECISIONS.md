## Phase 2 — the course correction (2026-07-24)

- 2026-07-24 — **REVERSED a wrong call from earlier the same day: all 21 `assets/protora/*.svg` had been imported as flat `staticAsset` art.** That made the app a sticker book — the user could place a radar scene but not change one ring of it, and nothing moved. The scenes are the ENGINE'S TARGET, not its content. `scripts/importAssets.mjs` now imports exactly one file (`logoMain.svg`); every scene is a composite ComponentDef built from primitives. Bundle went 1.4 MB → 293 KB as a side effect. Written up in `docs/NORTH_STAR.md`, which now outranks any plan step that contradicts it.
- 2026-07-24 — Added `docs/NORTH_STAR.md` as the first file to read every session. PLAN.md says how; NORTH_STAR says what for. Existing because the objective drifted once already.
- 2026-07-24 — `AnimBehavior` (contract `types.ts`) gained one member: `march` (dashes travelling along a stroke). Purely additive; the HUD language leans on marching dashes and faking it with `drawOn` looked wrong.
- 2026-07-24 — `reticle` gained `innerRadius`, `ringSpacing` and `centerGap` props so the generic component can reproduce the approved P-logo reticle EXACTLY (r=77.66, step 25.125, crosshair breaking at the inner ring) instead of `logoP` carrying a second private copy of that geometry. The mask and the editable node are now the same numbers.
- 2026-07-24 — `ringSet` gained `labelRole`; NM labels have to read on a dark scope disc as well as on the light page, and `ink` can't do both.
- 2026-07-24 — `arcSignal` gained `baseAngleDeg`. Mirroring one fan is what makes `focusArcs` (Group 344) a composition rather than a new component.
- 2026-07-24 — Colorway `alert.accent` changed from `electronicIceBlue` to `redAlert`. The hot skin is near-monochrome in the source kit (PLAN.md §3 calls redAlert the hot accent); cyan is the sparingly-used `electric` role (Group 81's outer ring). Big cyan `87%` readouts were the tell.
- 2026-07-24 — Store extensions beyond `contract.ts` (both logged on the type): `addAsset` (asset drop in one undo step) and `ungroupSelection` (grouping was a one-way door without it).
- 2026-07-24 — Knockout slots are rendered by the HOST, not by `RenderNode`. An SVG mask can't reach sibling DOM, and `RenderNode` composes the tree as nested divs. `RenderNode` therefore skips slots whose `SlotDef.mode === "knockout"`; `defs/logoP.tsx` draws its own.
- 2026-07-24 — Slot content's `layout.x/y` is RELATIVE to the slot frame (`replaceSlot` now seeds `{x:0,y:0,w:frame.w,h:frame.h}`). Absolute host coordinates would double-offset once the host applies the frame.
- 2026-07-24 — Cascade semantics implemented as: a child with `animation.enabled === false` inside a cascading parent inherits the parent's timing, with its own `delayMs` added as an offset. A child that sets its own `enabled` wins outright (per `types.ts`).
- 2026-07-24 — Added `src/lib/flattenSvg.tsx` (tree → one pure-SVG element tree, nested `<svg>` viewports instead of divs) plus `npm run shots` / `npm run smoke`. Verifying rendering headlessly beat guessing, and `flattenSvg` is the front half of the Phase 6 export pipeline rather than throwaway test code.
- 2026-07-24 — `markLockup` and `heroLockup` are two component kinds, not one with a layout switch. A `layoutMode` prop would have to regenerate children on change and would silently discard the user's edits to them.

## Phase 3 — making every control real (2026-07-24)

Triggered by a review that found the inspector promising things the renderer ignored.

- 2026-07-24 — **`AnimationConfig` gained `inherit: boolean` (contract change, additive).** `enabled: false` on a part inside a cascading scene did NOT stop it: `RenderNode` treated "disabled" as "inherit the parent's timing", so the Animate toggle was a no-op on exactly the nodes users reach for. Now `enabled` is absolute per node, `inherit` selects the timing source, and a disabled cascading parent also silences the descendants that inherit from it (turn a scene off at the top and the whole scene rests). Asserted in `npm run smoke`, which now fails if any of the four state rules regress.
- 2026-07-24 — Cascade resolution moved into `src/components-model/animResolve.ts` and is shared by `RenderNode`, the hierarchy badges and the inspector. Two copies of this logic is how the panels came to disagree with the renderer in the first place.
- 2026-07-24 — **Resizing a node with children now scales those children** (`scaleSubtree` in `state/store.ts`). A group's box IS the frame of its parts, so width/height was previously a dead control on every scene and lockup. Stroke widths deliberately do not scale (PLAN.md §5.1); `style.strokeScale` remains the control for that.
- 2026-07-24 — Nested parts get an editor-only drag/resize handle overlaid on the selected node (`components/Canvas/ChildHandle.tsx`), positioned from the model rather than from the DOM. Rejected the alternative of wrapping every tree level in react-rnd: `RenderNode` is also used by thumbnails, previews and (soon) export, and none of those want editor chrome. Slot content is intentionally not draggable — its position is the host's `SlotDef.frame`.
- 2026-07-24 — Selection follows Figma once inside a group: plain clicks pick sibling parts, locked parts are stepped over rather than blocking the pick, root dragging stands down while a part is selected, and esc/↩ step out/in.
- 2026-07-24 — Added `src/components-model/introspect.ts`: a kind's used color roles / stroke usage / seed sensitivity are DERIVED by calling its own `Render` with a spying `color()` and walking the result, then cached per kind. The alternative was annotating 25 def files and keeping the annotations honest by hand. The inspector uses it to drop controls that would do nothing (seven role pickers on a one-color component, stroke weight on a text block, Shuffle on a component that ignores its seed, colorway on a pure container).
- 2026-07-24 — Inspector sections are now conditional and carry state badges, plus a breadcrumb of the selection path. An identical panel on every layer was making it impossible to tell which of five near-identical rings was selected.
- 2026-07-24 — `vectorLine` gained `origin`, `fitBox` and `showOrigin`. `fitBox` makes a line's length follow its box, which is what lets a rule scale with the group it's in.
- 2026-07-24 — The lockups' underline stopped being host-drawn geometry behind an `underline` prop and became a real `vectorLine` child; their radar parts are wrapped in one `composite` group. Both hosts now draw nothing and expose no props — everything visible in a lockup is a selectable part, and the radar moves and scales as a unit. Dead `underline` prop removed rather than kept for compatibility (no saved documents exist yet).
- 2026-07-24 — Asset id renamed `protonWordmark` → `protoraWordmark` and the label corrected. The brand is PROTORA; the old id came from a misread of the logo file.

## Phase 3b — contacts that move (2026-07-24)

- 2026-07-24 — **`AnimBehavior` gained `drift` (contract change, additive), and `orbit` — declared since Phase 0 — is now implemented.** Every behavior up to here only restyled a component in place (opacity, scale, dash, rotation about its own centre); nothing on a scope ever changed position, so a radar full of blinking dots read as a texture rather than as tracked movement. `drift` wanders each element around its home position; `orbit` walks a whole blip formation around the middle of its field.
- 2026-07-24 — Travel is implemented with SMIL `animateMotion` along a seeded **closed** route (`wanderPath` in `src/lib/anim.ts`, Catmull-Rom through jittered waypoints). Closed and starting at the origin is what preserves invariant #4: t=0 equals the element's base position, so the paused editor frame and the exported static SVG both show exactly the layout the user arranged. Rejected animating `x`/`y`/`transform` directly — a translate animation would fight the transforms components already use for placement and heading.
- 2026-07-24 — Motion helpers (`wanderPath`, `speedOf`, and `cycle`'s new per-element duration override) live in `src/lib/anim.ts`, not in `blipField`. `craft` and `targetGlyph` picked up `drift` for ~6 lines each as a result — a loitering drone and a tracked single contact are the same idea at a different scale.
- 2026-07-24 — Each contact gets its own seeded speed (`speedOf`, 0.75–1.45× the node's duration) and phase. Identical timing across a field reads as one mechanism turning, not as separate things being tracked.
- 2026-07-24 — Track trails are ghost copies of the SAME motion started later, so a trail is always exactly the route the contact took. Ghosts are emitted only while animating: they are a motion artifact, and a static export should not show three stacked dots.
- 2026-07-24 — `ControlMeta.visibleWhen` now receives the whole node as a second argument (contract change, additive; call site is `Inspector/PropsSection.tsx`). Movement-shaping props (wander radius, route legs, trail) depend on `animation.behavior`, which is not in props, and showing dead controls is the exact problem Phase 3 set out to fix. Speed stays in the Animation section, where every kind's timing lives.
- 2026-07-24 — `hydrateNode` now backfills props from the kind's factory (`{...factory().props, ...saved}`). Adding `driftRadius` would otherwise have rendered NaN paths in any document saved beforehand; this makes every future prop addition backwards compatible instead of one-off.
- 2026-07-24 — Scene defaults switched from flicker to movement where the reference implies tracking: `radarScope` contacts drift, its friendlies orbit as a formation, its three hostiles drift fast with three-step trails; `telemetryPanel` contacts drift; both lockups drift subtly (a logo still has to read as a logo). `drift` is also the first-declared blip behavior, so a newly added Blip Field moves by default.

## Phase 6 — Export (2026-07-24)

Full write-up: `docs/EXPORT.md`. Only the irreversible calls are logged here.

- 2026-07-24 — **Export serializes the MODEL, not the canvas DOM — the one real structural departure from the reference app.** Helix registers each live `<svg>` in `svgRegistry` and clones it; that works there because one graphic is one `<svg>`. Here `RenderNode` composes a tree with nested `<div>`s (PLAN.md §5.1, so parent transforms can't distort child strokes), so a group's DOM is HTML containing sibling `<svg>`s — cloning it produces a file nothing else can open. `src/lib/flattenSvg.tsx` (built in Phase 2 for previews) re-composes any subtree with nested `<svg>` viewports, and that is what gets serialized. One code path covers a part, a group, a scene and the canvas.
- 2026-07-24 — **`src/lib/svgRegistry.ts` deleted** (it was a Phase-0 port, wired to nothing but `NodeLayer`'s registration effect). Keeping a DOM registry the export pipeline never reads would have sent the next session down the wrong road.
- 2026-07-24 — Static export renders with `animate: false` instead of stripping SMIL nodes from finished markup (which is what the reference does, plus a `FREEZE_ATTRS` baking table for the cases where base ≠ resting). Emitting the paused frame needs no baking table and can't drift out of sync with the animation code, because invariant #4 already requires base attributes to equal the finished frame. The cost is that a component which violates that invariant fails silently in static export — so `npm run smoke` asserts zero SMIL and no HTML in every kind's static output.
- 2026-07-24 — Accepted `react-dom/server` in the browser bundle (306 KB → 385 KB raw, +25 KB gzip) rather than rendering into a detached DOM container with `createRoot`/`flushSync` + `XMLSerializer`. `renderToStaticMarkup` is what `scripts/preview.tsx` and `scripts/smoke.tsx` already use, so the file a user downloads is byte-identical to what CI-style checks look at — worth 25 KB in a desktop design tool. Revisit only if first-load size ever matters (a dynamic `import()` would move it to a lazy chunk at the cost of making serialization async).
- 2026-07-24 — `flattenSvg` was still carrying the pre-Phase-3 copy of the animation-cascade logic and now calls `resolveAnimation` like `RenderNode`. It had silently reverted to "disabled means inherit", i.e. the exact bug Phase 3 fixed on canvas — which would have exported animation the user had switched off.
- 2026-07-24 — PNG is always rasterized from the STATIC frame: an `<img>` runs a SMIL clock that can't be seeked, so an animated source would freeze at an arbitrary moment. Scale is clamped to Safari's ~16M px canvas ceiling and the filename records the scale actually used — a silently blank 4× PNG is worse than a smaller one.
- 2026-07-24 — Node exports are framed to the node's own box + 24px padding (not canvas coordinates), and a rotated node is framed to its rotated bounding box. A root `<svg>` clips, unlike the canvas where CSS overflow is visible, so without this a rotated part loses its corners.
- 2026-07-24 — One `ExportActions` component serves both surfaces (toolbar popover with a Selection/Canvas switch, inspector Export section). Two export UIs would drift apart the moment a format is added; adding a button in one place now lights up both.
- 2026-07-24 — `hydrateNode` exported from the store so the smoke test can round-trip a `.dkl.json` exactly the way `loadDoc` does, and the toolbar grew **Open** — an export format you can't reopen isn't a format, and it makes PLAN.md §11 Phase 6's determinism criterion testable.

## Phase 5 — Library, Composer, variations (2026-07-25)

The mission was written down first (`docs/MISSION.md`), then audited against the app (`docs/RECOMMENDATION.md`). The gap it found: the engine had no memory — nothing a user refined could re-enter the system, so every session restarted from factory defaults. Everything below closes that loop.

- 2026-07-25 — **Adopted a three-layer vocabulary** (`docs/RECOMMENDATION.md` §1): *Definition* = `ComponentDef`, code, the grammar; *Instance* = `ComponentNode` on the canvas; *Saved entry* = `LibraryEntry`, a frozen subtree + approval state. Most "we need a new component" moments are layer 3, and conflating the layers is what makes people reach for code when a saved assembly would do.
- 2026-07-25 — **A saved entry is DATA and is never registered as a component kind.** Registering user entries at runtime would make the gallery uniform, but a `.dkl.json` would then reference a kind that exists only in one browser's localStorage: the file opens nowhere else and `npm run smoke` can't enumerate it. Placing an entry INLINES a fresh-id clone (`instanceOf`), with `provenance.baseComponent` recording the origin so "update from library" stays possible later.
- 2026-07-25 — **One library, not two.** Refined parts and composed HUDs are the same object (a node subtree), so `scope: "part" | "assembly"` is DERIVED from the tree and used only as a filter. Two parallel libraries would fracture the taxonomy and hand Phase 7 two APIs for one idea.
- 2026-07-25 — Library entries carry **no stored thumbnail**. Cards render the stored node through the same `RenderNode` the canvas uses, so a preview cannot drift from what placing it produces, and localStorage isn't holding tens of KB of SVG per entry. Reversed the plan's original "store a serialized thumbnail" call. (`Thumbnail` grew a `node` prop and keeps the entry's own seed — re-seeding a saved entry's preview would show a tree the placement won't produce.)
- 2026-07-25 — Store extensions beyond `contract.ts`, all logged on the type: the whole `library` slice, `mode`/`composer`/`stageStash`, `applyVariation`, and the exposed-control actions. `savePreset`/`loadPreset` from the contract replace the WHOLE document, which makes them a save-file mechanism, not a library; they are left in place, unused by the UI.
- 2026-07-25 — **The Composer is a MODE over the same store, not a second canvas.** Entering stashes the stage document (`stageStash`) and swaps `nodes` for the artifact, so every existing action, panel, keyboard shortcut and export path works unchanged. A second tree would have meant a second copy of all of it, and a forked renderer is how WYSIWYG quietly dies. Undo is covered because the stash carries the stage's history stacks with it.
- 2026-07-25 — **The composer's whole stage is the artifact** (`composerArtifact`): one root saves as itself, several are wrapped in a `composite` framed to their union box. This is what makes multi-part assembly possible at all today — `groupSelection` still groups a SINGLE node (no marquee, no ⌘-click), so "assemble eight parts and save them as one thing" is impossible on the stage. The Composer sidesteps the missing multi-select instead of waiting for it.
- 2026-07-25 — `composerPlaceOnStage` writes into the stash, not the live document, and pushes its own entry onto the STAGE's undo history — the stage is where a user would look to undo it.
- 2026-07-25 — **`ComponentNode` gained `exposed?: ExposedParam[]` (contract change, additive).** Promoted knobs address their target by **child-index path, never by id**, because placing a library entry clones the tree with fresh ids; an id-based mapping would break on the first placement. Asserted in `npm run smoke` (the clone test proves index paths survive where id lookup returns null). Rejected storing the map in `CompositeProps`: knobs are useful on `radarScope` and `launchKit` too, and props are per-kind.
- 2026-07-25 — Variations are **deterministic and offset-addressed** (`lib/variations.ts`): variant *i* is a pure function of base, axes and index, and "More" walks to batch *n+1* of one infinite sequence rather than re-rolling. Axes only move values the registry already declares — seeds it uses, colorways it resolves through, controls it publishes — so a variation cannot leave the brand system. Density matches control keys by regex against each kind's own `controls`, so a new component with a `count` prop joins in without a table entry.
- 2026-07-25 — **Added `npm run conform` as a gate, and `docs/EXTENDING.md` as its rulebook.** `smoke` asks "does it render?"; `conform` asks "is it part of the system?" — no raw hex in def files, no off-palette color in rendered output, every factory prop reachable by a control (and vice versa), deterministic renders, static frame = resting frame, metadata present. Discipline doesn't scale when the next author is a model that never read a doc. Verified it bites before trusting it.
- 2026-07-25 — Two findings from writing that gate, both real: `staticAsset`'s factory omitted its optional `inkRole`, so the control drove a prop the factory never declared — factories now list every prop they support, `undefined` included. And rule 7 originally read the whole subtree's SMIL, which failed the lockups for their children's animation; it now reads only `def.Render`'s own output.
- 2026-07-25 — Saving takes no dialog: `Save to Library` uses the node's current name (already editable in the inspector) and confirms inline, with rename living on the library card. A modal per save is friction on the action this whole pass exists to encourage, and ⌘S works instantly because of it.
- 2026-07-25 — **Export composes with `<g transform>`, not nested `<svg>` viewports** (`lib/flattenSvg.tsx`). Nested viewports were the literal translation of the canvas's positioned divs and browsers render them correctly, so this looked right for months — but Figma's importer ignores an inner `viewBox` scale and clips to the frame, so every pasted mark arrived cropped and small. Flatten now resolves x/y, `viewBox` and `preserveAspectRatio` into transforms itself, recursing through each component's own render output too (`logoP` nests a viewport to draw its slot). Only the document root is an `<svg>` now. Rejected "paste PNG instead": the point of the mark is that it stays vector.
- 2026-07-25 — **Fixed art declares `aspectOf` on its `ComponentDef`** (`logoP`, `staticAsset`, both lockups). Generated parts restate their geometry at any box, so they fill it; fixed art fits into a native viewBox with `xMidYMid meet` and letterboxes the moment the box goes off-ratio — art shrinking inside a box that handles, group bounds and export all still measure at full size. `patchLayout`, `patchProps` (an `assetId` swap changes the ratio) and `scaleSubtree` hold the box on the ratio, and the resize handles lock to it. Chose to constrain the box rather than stretch the art: a squashed mark is off-brand, so the distorted state should be unreachable, not merely compensated for.
