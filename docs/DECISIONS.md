One line each: date — decision — why. Append only; don't rewrite history.

- 2026-07-24 — Adopted the 5 Helix-Studio invariants + 2 new ones as binding (PLAN.md §4/§11): WYSIWYG export, one source of truth per concern, store-actions-only mutation, factory-hydrated serialization, no model calls outside the sidecar, deterministic seeded rendering, protected presets always fork.
- 2026-07-24 — Phase 0: moved `elements/` → `assets/protora/` with plain `mv` (not `git mv`) because the repo had no commits yet; `git init -q` also required `required_permissions: ["all"]` in this sandbox (hooks dir write). No content changes to the SVGs.
- 2026-07-24 — Phase 0: pinned `zod` to `^4.4.3` (matching the reference app) rather than a v3 range, since `src/lib/ai/patchSchema.ts` was authored against the v4 API (two-arg `z.record`, etc.).
- 2026-07-24 — Phase 0: trimmed `controlSpec.ts` during the port — dropped Helix's genetics/map-specific control kinds (`maptheme`, `fillmap`, `wheelway`; Helix's `colorway` meant research-palette ramps). Kept `hint`/`group`/`visibleWhen` and generic kinds (number/text/toggle/color/select/image/labellist). Darklighter's `colorway` kind now refers to the Protora `alert`/`chrome`/`custom` colorway (`src/lib/colorway.ts`), a different concept with the same control-kind name.
- 2026-07-24 — Phase 0: `src/state/store.ts` is an explicitly partial "Phase 0 scaffold store" (windows/background/selection only, `nodes` hardcoded to `[]`). It is NOT an implementation of `DarklighterStore` from `contract.ts` — that is Phase 1 step 2. Said so in a header comment to prevent the next session from assuming Phase 1 is done.
- 2026-07-24 — Phase 0: `fields.tsx`'s `ColorInput` swatches now come from `BRAND_SWATCHES` (`src/lib/colorway.ts`) instead of Helix's per-project "active color board" store dependency — Darklighter has no such board concept; colorway is a per-node `style.colorway` property instead.
- 2026-07-24 — Phase 0: canvas coordinate space set to 1600×1200 (PLAN.md §6), not Helix's 1600×900 — Darklighter isn't hero-image-shaped.

## Phase 2 — the course correction (2026-07-24)

- 2026-07-24 — **REVERSED a wrong call from earlier the same day: all 21 `assets/protora/*.svg` had been imported as flat `staticAsset` art.** That made the app a sticker book — the user could place a radar scene but not change one ring of it, and nothing moved. The scenes are the ENGINE'S TARGET, not its content. `scripts/importAssets.mjs` now imports exactly one file (`logoMain.svg`); every scene is a composite ComponentDef built from primitives. Bundle went 1.4 MB → 293 KB as a side effect. Written up in `docs/NORTH_STAR.md`, which now outranks any plan step that contradicts it.
- 2026-07-24 — Added `docs/NORTH_STAR.md` as the first file to read every session. PLAN.md says how; NORTH_STAR says what for. Existing because the objective drifted once already.
- 2026-07-24 — `AnimBehavior` (contract `types.ts`) gained one member: `march` (dashes travelling along a stroke). Purely additive; the HUD language leans on marching dashes and faking it with `drawOn` looked wrong.
- 2026-07-24 — `reticle` gained `innerRadius`, `ringSpacing` and `centerGap` props so the generic component can reproduce the approved P-logo reticle EXACTLY (r=77.66, step 25.125, crosshair breaking at the inner ring) instead of `logoP` carrying a second private copy of that geometry. The mask and the editable node are now the same numbers.
- 2026-07-24 — `ringSet` gained `labelRole`; NM labels have to read on a dark scope disc as well as on the light page, and `ink` can't do both.
- 2026-07-24 — `arcSignal` gained `baseAngleDeg`. Mirroring one fan is what makes `focusArcs` (Group 344) a composition rather than a new component.
- 2026-07-24 — Colorway `alert.accent` changed from `electronicIceBlue` to `redAlert`. The hot skin is near-monochrome in the source kit (PLAN.md §3 calls redAlert the hot accent); cyan is the sparingly-used `electric` role (Group 81's outer ring). Big cyan `87%` readouts were the tell.
- 2026-07-24 — Store extensions beyond `contract.ts` (both logged on the type): `addAsset` (asset drop in one undo step) and `ungroupSelection` (grouping was a one-way door without it).
- 2026-07-24 — Knockout slots are rendered by the HOST, not by `RenderNode`. An SVG mask can't reach sibling DOM, and `RenderNode` composes the tree as nested divs. `RenderNode` therefore skips slots whose `SlotDef.mode === "knockout"`; `defs/logoP.tsx` draws its own.
- 2026-07-24 — Slot content's `layout.x/y` is RELATIVE to the slot frame (`replaceSlot` now seeds `{x:0,y:0,w:frame.w,h:frame.h}`). Absolute host coordinates would double-offset once the host applies the frame.
- 2026-07-24 — Cascade semantics implemented as: a child with `animation.enabled === false` inside a cascading parent inherits the parent's timing, with its own `delayMs` added as an offset. A child that sets its own `enabled` wins outright (per `types.ts`).
- 2026-07-24 — Added `src/lib/flattenSvg.tsx` (tree → one pure-SVG element tree, nested `<svg>` viewports instead of divs) plus `npm run shots` / `npm run smoke`. Verifying rendering headlessly beat guessing, and `flattenSvg` is the front half of the Phase 6 export pipeline rather than throwaway test code.
- 2026-07-24 — `markLockup` and `heroLockup` are two component kinds, not one with a layout switch. A `layoutMode` prop would have to regenerate children on change and would silently discard the user's edits to them.

## Phase 3 — making every control real (2026-07-24)

Triggered by a review that found the inspector promising things the renderer ignored.

- 2026-07-24 — **`AnimationConfig` gained `inherit: boolean` (contract change, additive).** `enabled: false` on a part inside a cascading scene did NOT stop it: `RenderNode` treated "disabled" as "inherit the parent's timing", so the Animate toggle was a no-op on exactly the nodes users reach for. Now `enabled` is absolute per node, `inherit` selects the timing source, and a disabled cascading parent also silences the descendants that inherit from it (turn a scene off at the top and the whole scene rests). Asserted in `npm run smoke`, which now fails if any of the four state rules regress.
- 2026-07-24 — Cascade resolution moved into `src/components-model/animResolve.ts` and is shared by `RenderNode`, the hierarchy badges and the inspector. Two copies of this logic is how the panels came to disagree with the renderer in the first place.
- 2026-07-24 — **Resizing a node with children now scales those children** (`scaleSubtree` in `state/store.ts`). A group's box IS the frame of its parts, so width/height was previously a dead control on every scene and lockup. Stroke widths deliberately do not scale (PLAN.md §5.1); `style.strokeScale` remains the control for that.
- 2026-07-24 — Nested parts get an editor-only drag/resize handle overlaid on the selected node (`components/Canvas/ChildHandle.tsx`), positioned from the model rather than from the DOM. Rejected the alternative of wrapping every tree level in react-rnd: `RenderNode` is also used by thumbnails, previews and (soon) export, and none of those want editor chrome. Slot content is intentionally not draggable — its position is the host's `SlotDef.frame`.
- 2026-07-24 — Selection follows Figma once inside a group: plain clicks pick sibling parts, locked parts are stepped over rather than blocking the pick, root dragging stands down while a part is selected, and esc/↩ step out/in.
- 2026-07-24 — Added `src/components-model/introspect.ts`: a kind's used color roles / stroke usage / seed sensitivity are DERIVED by calling its own `Render` with a spying `color()` and walking the result, then cached per kind. The alternative was annotating 25 def files and keeping the annotations honest by hand. The inspector uses it to drop controls that would do nothing (seven role pickers on a one-color component, stroke weight on a text block, Shuffle on a component that ignores its seed, colorway on a pure container).
- 2026-07-24 — Inspector sections are now conditional and carry state badges, plus a breadcrumb of the selection path. An identical panel on every layer was making it impossible to tell which of five near-identical rings was selected.
- 2026-07-24 — `vectorLine` gained `origin`, `fitBox` and `showOrigin`. `fitBox` makes a line's length follow its box, which is what lets a rule scale with the group it's in.
- 2026-07-24 — The lockups' underline stopped being host-drawn geometry behind an `underline` prop and became a real `vectorLine` child; their radar parts are wrapped in one `composite` group. Both hosts now draw nothing and expose no props — everything visible in a lockup is a selectable part, and the radar moves and scales as a unit. Dead `underline` prop removed rather than kept for compatibility (no saved documents exist yet).
- 2026-07-24 — Asset id renamed `protonWordmark` → `protoraWordmark` and the label corrected. The brand is PROTORA; the old id came from a misread of the logo file.

## Phase 3b — contacts that move (2026-07-24)

- 2026-07-24 — **`AnimBehavior` gained `drift` (contract change, additive), and `orbit` — declared since Phase 0 — is now implemented.** Every behavior up to here only restyled a component in place (opacity, scale, dash, rotation about its own centre); nothing on a scope ever changed position, so a radar full of blinking dots read as a texture rather than as tracked movement. `drift` wanders each element around its home position; `orbit` walks a whole blip formation around the middle of its field.
- 2026-07-24 — Travel is implemented with SMIL `animateMotion` along a seeded **closed** route (`wanderPath` in `src/lib/anim.ts`, Catmull-Rom through jittered waypoints). Closed and starting at the origin is what preserves invariant #4: t=0 equals the element's base position, so the paused editor frame and the exported static SVG both show exactly the layout the user arranged. Rejected animating `x`/`y`/`transform` directly — a translate animation would fight the transforms components already use for placement and heading.
- 2026-07-24 — Motion helpers (`wanderPath`, `speedOf`, and `cycle`'s new per-element duration override) live in `src/lib/anim.ts`, not in `blipField`. `craft` and `targetGlyph` picked up `drift` for ~6 lines each as a result — a loitering drone and a tracked single contact are the same idea at a different scale.
- 2026-07-24 — Each contact gets its own seeded speed (`speedOf`, 0.75–1.45× the node's duration) and phase. Identical timing across a field reads as one mechanism turning, not as separate things being tracked.
- 2026-07-24 — Track trails are ghost copies of the SAME motion started later, so a trail is always exactly the route the contact took. Ghosts are emitted only while animating: they are a motion artifact, and a static export should not show three stacked dots.
- 2026-07-24 — `ControlMeta.visibleWhen` now receives the whole node as a second argument (contract change, additive; call site is `Inspector/PropsSection.tsx`). Movement-shaping props (wander radius, route legs, trail) depend on `animation.behavior`, which is not in props, and showing dead controls is the exact problem Phase 3 set out to fix. Speed stays in the Animation section, where every kind's timing lives.
- 2026-07-24 — `hydrateNode` now backfills props from the kind's factory (`{...factory().props, ...saved}`). Adding `driftRadius` would otherwise have rendered NaN paths in any document saved beforehand; this makes every future prop addition backwards compatible instead of one-off.
- 2026-07-24 — Scene defaults switched from flicker to movement where the reference implies tracking: `radarScope` contacts drift, its friendlies orbit as a formation, its three hostiles drift fast with three-step trails; `telemetryPanel` contacts drift; both lockups drift subtly (a logo still has to read as a logo). `drift` is also the first-declared blip behavior, so a newly added Blip Field moves by default.
